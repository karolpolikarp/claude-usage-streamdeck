// how it works

The four limit keys

One call a minute to Anthropic's usage endpoint, authenticated with the token Claude Code already stores. No separate login, no API key to paste.

An expired token is refreshed and written back, so Claude Code and the plugin keep sharing one credential. A 429 is respected: the plugin reads retry-after, retries once, and mutes its own timer for that window instead of piling on.

Cost today

Never touches the network. It reads your local Claude Code transcripts, counts today's tokens per model, and prices them — with the separate multipliers for 5-minute cache writes, 1-hour writes, and reads.

Files are read incrementally from the last byte offset, so a poll costs about 40 ms after the first scan of the day. The figure is notional: on a subscription nothing is billed, it just tells you how hard the day has been.

Then drag the keys from the Claude category onto your deck. Needs Stream Deck 6.5+ — the plugin runs on the Node runtime the app already ships with — and Claude Code logged in.

What it does with your data

// it reads your credentials, so:
network
Two hosts, nothing else. Anthropic's API for usage, and the token endpoint when a refresh is due. No telemetry, no analytics, no third parties.
transcripts
Message content is never read. The cost scan pulls token counts and timestamps out of the JSONL and nothing else — and it never leaves your machine.
credentials
Written back only on expiry. The refreshed token is written atomically, keeping the previous file as .credentials.json.sdbak.
audit
Six files under 400 lines. No build step, one dependency, MIT licensed — read it in a sitting.
